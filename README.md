# VisaPics Mobile

Passport and visa photos that pass, for iOS and Android. React Native on Expo
SDK 57.

The app is a client of the [visapics.org](https://visapics.org) API and holds no
business logic the server does not also hold. What it adds is the part a website
cannot do: live on-device coaching that measures head size, centring, lighting
and background against the selected document's specification while you line up
the shot, and keeps the shutter locked until all four pass.

## Status

Early. The project scaffold, native configuration and CI are in place; the
screens are being built.

## Running it

```bash
npm ci
npx expo prebuild        # generates ios/ and android/, which are git-ignored
npx expo run:ios         # or: npx expo run:android
```

`ios/` and `android/` are generated by [prebuild][cng] rather than committed, so
`app.json` stays the single source of native configuration. Editing the
generated projects directly means losing the edit on the next prebuild.

Building for iOS needs Xcode; building for Android needs the Android SDK and
JDK 17.

[cng]: https://docs.expo.dev/workflow/continuous-native-generation/

## CI

- **PR checks** — TypeScript and tests, on every pull request and push to main.
- **Build** — run manually from the Actions tab, choosing Android, iOS or both.
  Android produces an APK; iOS produces an unsigned IPA, which proves the native
  build compiles without putting a signing certificate in a public repository.

## Why this repository is public

It contains nothing secret. The API base URL is public, OAuth client identifiers
for native apps are public by Apple's and Google's design, in-app purchase
product identifiers are public, and the app authenticates with a user token
rather than an API key. Signing certificates, provisioning profiles and keystores
are excluded by `.gitignore` and live only in GitHub Secrets.

Public also means macOS runners are free, so an iOS build can be produced
without a Mac being awake.
